Notion AI：出错时的兜底

Notion AI: Failure Fallbacks

今天拆什么：Notion AI 生成失败时（网络、超时、额度用尽），怎么保住你的原文 —— 错误态不弹窗，原文无损，内联重试。

What we're tearing down: when Notion AI generation fails (network, timeout, quota exhausted), how it protects your original text — no modal, zero data loss, inline retry.

①Trust calibration 做得怎么样？How is trust calibrated?

Notion AI 几乎不用数字置信度。它用的是结构型 calibration：AI 输出默认永远是 provisional（暂存的） —— 生成完必须经过 Replace 替换 / Insert below 插入 / Discard 丢弃 / Try again 重试 这道显式确认，输出才能真正进入你的文档。在你点确认之前，原文一字不动。

  • calibration 不表达在"AI 有多确定"，而表达在"AI 的输出有多临时"—— 比数字更诚实。
  • 代价：每次都要多点一次，用交互成本换确定性。对比 Day 1 的 Copilot：补全一行代码错了删掉就行，所以 calibration 压到一次击键；整段重写会覆盖你的文字，所以必须显式确认 —— calibration 的成本应该跟出错的代价成正比。

Notion AI barely uses numeric confidence. Instead it calibrates structurally: AI output is always provisional by default — after generation it must pass an explicit confirmation step (Replace / Insert below / Discard / Try again) before it truly enters your document. Your original text stays untouched until you confirm.

  • Calibration is expressed not as "how sure is the AI" but as "how provisional is the AI's output" — more honest than any number.
  • The price: one extra click every time, trading interaction cost for certainty. Compare Day 1's Copilot: a wrong line completion is trivial to delete, so calibration is squeezed into a single keystroke; a full rewrite could overwrite your words, so explicit confirmation is required — the cost of calibration should scale with the cost of being wrong.

②Graceful degradation 在哪？Where is graceful degradation?

失败时降级是归零，不是乱给：

  • 生成中途失败 → 内联显示错误 + Retry，原文一字未动。最差情况 = "什么都没发生"，而不是半截残次输出。
  • 额度用尽 → 明确告诉你不能用了（附升级路径），而不是静默失败或给残缺结果。
  • 错误信息说什么不说什么：说发生了什么（生成失败）+ 你能做什么（重试）；不说技术细节（不甩 error code 给用户）、不假装成功（不把半截输出当结果塞给你）。
  • 离线时 AI 按钮直接不可用 —— 而不是点下去再失败。

On failure, degradation returns to zero instead of delivering something broken:

  • Mid-generation failure → inline error + Retry, original text untouched. The worst case is "nothing happened", not a half-baked partial output.
  • Quota exhausted → it tells you plainly that it can't continue (with an upgrade path), instead of failing silently or returning truncated results.
  • What error copy says and doesn't say: it says what happened (generation failed) + what you can do (retry); it doesn't dump technical details (no error codes thrown at users) and never pretends success (no passing off partial output as a result).
  • Offline, the AI entry points are simply unavailable — rather than letting you click and fail.

③人有没有 override 的机会？Can the human override?

  • 生成完的选择行（Replace / Insert below / Discard / Try again / 继续追问）本身就是 override 界面。
  • 粒度同构：AI 按"一次生成"为单位输出，人按"一次生成"接受 / 拒绝 / 重试 —— 和 Day 1 的结论呼应：override 必须和 AI 输出同粒度。
  • 重试（Try again）是第二层 override：不满意时不是只有"接受"或"丢弃"，还能让 AI 换一个答案 —— "拒绝"和"重做"之间的第三条路。
  • 成本极低：一次点击；接受后反悔还有 Cmd+Z 兜底。时机：生成完立刻选，也可以 Discard 稍后再试。
  • The post-generation choice row (Replace / Insert below / Discard / Try again / follow-up prompt) is the override interface.
  • Matching granularity: the AI outputs in units of "one generation", and the human accepts / rejects / retries per generation — echoing Day 1's conclusion: override must match the AI's output granularity.
  • Try again is a second layer of override: when unsatisfied, you're not stuck with "accept" or "discard" — you can ask the AI for another answer. A third path between rejecting and redoing.
  • Cost is minimal: one click; and Cmd+Z still backs you up if you regret accepting. Timing: decide right after generation, or discard and retry later.

设计师 takeaway：graceful degradation 的第一原则是"永远别动用户已有的东西" —— AI 输出默认 provisional，失败时归零不乱给。以及错误文案公式：只说"发生了什么 + 你能做什么"，不甩技术细节、不假装成功。

Designer takeaway: The first principle of graceful degradation is "never touch what the user already has" — AI output is provisional by default, and failure degrades to zero, never to something broken. And the error-copy formula: only say "what happened + what you can do"; no technical dumps, no pretending success.

🎙️ 面试怎么讲：Notion AI 的出错兜底让我学到一条：graceful degradation 从"别丢用户东西"开始 —— 输出永远是 provisional 的，显式确认才写入，所以失败时最差情况就是"什么都没发生"，重试零成本。我在 AI Hub 里把这个做成一条原则：任何 AI 动作失败，用户原文和已有状态必须 100% 无损。

🎙️ How to say it in an interview: Notion AI's failure fallbacks taught me one rule: graceful degradation starts with "never lose the user's stuff" — output is always provisional, written only on explicit confirmation, so when generation fails the worst case is "nothing happened" and retry costs zero. I turned this into a principle in AI Hub: whenever any AI action fails, the user's original text and existing state must be 100% intact.
