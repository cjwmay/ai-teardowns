GitHub Copilot：行内补全的不确定性表达

GitHub Copilot: Expressing Uncertainty in Inline Completions

今天拆什么：写代码时，Copilot 用灰色 ghost text 实时推整行补全 —— Tab 接受、Esc 取消。不确定时它不会弹窗解释，只会给得更短，或干脆不给。

What we're tearing down: while coding, Copilot pushes whole-line completions as gray ghost text — Tab to accept, Esc to dismiss. When uncertain, it never pops up an explanation; it just suggests less, or stays silent.

①Trust calibration 做得怎么样？How is trust calibrated?

聪明，但有取舍。它刻意不显示数字置信度 —— 因为 LLM 的置信度本身就不准，显示 87% 只会制造虚假的精确感（false precision）。

  • 取而代之的是视觉 + 交互成本：灰色 = "这是草稿，不是答案"；接受 / 拒绝都只要一次击键，猜错了也不心疼。
  • 弱点：95% 确定和 50% 瞎猜看起来完全一样，用户只能靠长期体感校准，UI 本身不帮你区分。这是 simplicity 和 transparency 的 trade-off。

Clever, with a trade-off. It deliberately shows no numeric confidence — because LLM confidence is itself poorly calibrated, and showing "87%" would manufacture false precision.

  • Instead it calibrates with visuals + interaction cost: gray means "this is a draft, not an answer"; accepting or dismissing costs a single keystroke, so a wrong guess is cheap.
  • The weakness: a 95% sure suggestion and a 50% wild guess look identical — users calibrate only through long-term feel; the UI doesn't help distinguish. A deliberate trade-off between simplicity and transparency.

②Graceful degradation 在哪？Where is graceful degradation?

藏在"给多少"里 —— 降级是连续的，不是二元的：

  • 不确定时自动降级：长补全 → 短补全 → 沉默。从不弹窗、从不打断心流。
  • 离线 / 出错时直接无建议，编辑器本身完全可用。
  • 核心洞察：AI 永远是增强层，不是依赖项 —— 最差情况就是回到没有 AI 的样子，核心任务永不断裂。

It's hidden in how much is suggested — degradation is continuous, not binary:

  • When uncertain, it degrades gracefully: long completion → short completion → silence. Never a modal, never breaks flow.
  • Offline or on error, there are simply no suggestions; the editor stays fully usable.
  • The core insight: AI is always an enhancement layer, never a dependency — the worst case is just "no AI", and the core task never breaks.

③人有没有 override 的机会？Can the human override?

  • 整行接受（Tab）、逐词接受（Ctrl+→）、拒绝（Esc）、多候选切换（Alt+[ / ]）、接受后直接改。
  • 关键设计：override 的粒度与 AI 生成的粒度一一对应 —— AI 给到词，人就能按词改。这比"一键全接受 / 推倒重来"的二选一高明得多。
  • Accept a line (Tab), accept word-by-word (Ctrl+→), dismiss (Esc), cycle alternatives (Alt+[ / ]), or just edit after accepting.
  • The key design move: override granularity matches generation granularity — the AI generates by the word, so the human can override by the word. Far better than a binary "accept all / rewrite everything".

设计师 takeaway：calibration 不一定要用数字 —— "草稿感视觉 + 一次击键的反悔成本"同样成立，甚至更诚实。以及：override 必须和 AI 输出同粒度，否则人要么全盘接受、要么推倒重来。

Designer takeaway: calibration doesn't need numbers — "draft-like visuals + one-keystroke reversibility" works just as well, and is arguably more honest. And override must match the AI's output granularity, or users face a false binary: accept all or redo everything.

🎙️ 面试怎么讲：Copilot 不用置信度数字做 trust calibration，而是用交互成本 —— 灰色 ghost text 加 Tab/Esc，让对错都只要一次击键。我在 AI Hub 里用了同一逻辑：AI 建议永远是 provisional 的，人的 override 成本必须小于等于 AI 的生成成本。

🎙️ How to say it in an interview: Copilot doesn't calibrate trust with confidence scores but with interaction cost — gray ghost text plus Tab/Esc makes being right or wrong cost a single keystroke. I applied the same logic in AI Hub: AI suggestions are always provisional, and the human's override cost must be less than or equal to the AI's generation cost.
